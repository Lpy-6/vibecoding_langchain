# 压测报告：100 并发用户模拟

- 日期：2026-10-28
- 工具：Locust 2.47（Python / requests，SSE 流式计时）
- 模式：`LLM_MODE=mock`（离线抽取式回答 + 本地哈希向量），零外部 API 依赖
- 隔离环境：独立 `data_stress/` 目录 + 8001 端口 + 限流阈值全部放开；生产 `data/` 演示库全程未被触碰（已核对文档时间戳）
- 数据：5 文档 / 52 子块种子知识库，100 个独立压测账号，问题池取自 `eval/golden/qa.jsonl`（20 条真实问题）
- 服务端：单进程 uvicorn + SQLite WAL（即项目实际部署形态）

## 结论（TL;DR）

**系统在 100 并发下零错误、零数据库锁冲突，容量达标。**
语义缓存是最大功臣：重复问题命中率 99.96%，命中路径平均仅 ~0.3ms；真实检索+生成路径平均 ~22ms。拐点出现在 100 并发（P95 跳升），60 并发内几乎无感。单进程内存稳定无泄漏。

问答完整回答 P95 3.7s（混合写入下比 S1 升高约 1.8s，仍低于 5s 阈值）。

### S3 阶梯加压：10 → 30 → 60 → 100 并发（每档 3 分钟）

| 并发 | 问答数 | 吞吐 (req/s) | 完整回答 P50 | P95 | P99 | 失败 |
|---|---|---|---|---|---|---|
| 10 | 887 | 4.95 | 18ms | 46ms | 73ms | 0 |
| 30 | 2,635 | 14.71 | 20ms | 80ms | 130ms | 0 |
| 60 | 5,056 | 28.27 | 35ms | 170ms | 360ms | 0 |
| 100 | 7,668 | 42.70 | 71ms | 1.1s | 2.4s | 0 |

**容量曲线结论**：
- 10–60 并发：延迟线性缓增，P95 始终 <200ms，体验无感
- 100 并发：吞吐仍在增长（42.7 req/s）但 P95 跳升 6.5 倍（170ms→1.1s），到达**软拐点**——单进程 uvicorn + SQLite 的饱和区
- 全程 0 错误、0 锁冲突，系统以"变慢"而非"崩溃"方式过载，符合优雅降级预期

## 瓶颈分析与后续建议（未改动生产代码）

1. **100 并发软拐点**：单进程 uvicorn 事件循环 + SQLite 串行写是主因。若需支撑更高并发，可多进程部署（SQLite 需换 PostgreSQL）——这是架构演进路径，当前单机规模无必要。
2. **S2 问答 P95 3.7s**：混合写场景下消息持久化与缓存写入和检索争抢 SQLite 写锁所致；WAL 模式已消除锁冲突（0 错误），仅表现为延迟上升。
3. **ramp-up 长尾**：100 用户瞬间涌入时建会话+首问集中落库，可在客户端加随机启动延迟（Locust 已用 10/s 匀速爬坡，长尾主要来自首波）。
4. mock 模式测的是系统自身开销；真实模型下延迟将由 DashScope API 主导（此前实测首 token P95 1.76s），结论同样支持"系统本身不是瓶颈"。
